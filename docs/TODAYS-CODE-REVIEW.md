## Canonical and resolver failures

- **THE CANONICAL REGISTRY STILL FAILS OPEN.** `crates/basilisk-canonical/src/registry.rs:90-107` logs a registry parse failure and installs an empty index. One bad registry entry disables every canonical lookup for the lifetime of the process while the application keeps running.
- **BINDING EVENTS ARE RECORDED BEFORE PYTHON CREATES THE BINDING.** `crates/basilisk-canonical/src/binding.rs:92-105,310-318` timestamps assignment, class, and function bindings at the start of the statement. A use in an assignment RHS, class base, or decorator can therefore resolve to the binding being defined instead of the previous binding.
- **LATER REBINDS STILL CORRUPT EARLIER BUILTIN USES.** `BindingTable::form_of_with_builtins` at `crates/basilisk-canonical/src/binding.rs:397-407` calls the whole-module existential `binds_name`; a binding appearing later in the file suppresses builtin recognition at an earlier use despite the table already storing positional events.
- **CONDITIONAL STUB IMPORTS ARE STILL FLATTENED INTO ONE FALSE GLOBAL VIEW.** `crates/basilisk-stubs/src/pyi_parser.rs:190-194,299-317` shares one binding table across mutually exclusive version and platform branches. An import in an infeasible later branch can determine what a use in the selected branch resolves to.
- **QUOTED QUALIFIERS ARE STILL LOST.** `crates/basilisk-resolver/src/visitor/annotations.rs:25-64` sends annotation expressions directly to canonical lookup, but canonical lookup cannot resolve `Expr::StringLiteral`. Explicitly quoted `Final`, `ClassVar`, `InitVar`, `KW_ONLY`, and `ReadOnly` therefore lose their qualifier flags.
- **ENUM CLASSIFICATION STILL VIOLATES ITS OWN CONTRACT.** `crates/basilisk-resolver/src/visitor/class_info_ext.rs:23-38,166-173` checks only direct canonical bases, while `ClassInfo::is_enum` promises direct or transitive classification at `scope/class_types.rs:111-114`.
- **TYPEVAR COLLECTION IS STILL INCOMPLETE.** `crates/basilisk-resolver/src/visitor/typevar.rs:41-78` drops declarations inside module-level `if`, `try`, `with`, loops, and `match`; `:151-163` also returns `false` for a bare known TypeVar used as a bound or constraint. Valid `if TYPE_CHECKING:` declarations disappear, while parameterized bounds evade checks.
